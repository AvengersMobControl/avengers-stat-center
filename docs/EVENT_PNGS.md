# AVENGERS / AV-2 event summary PNGs — repeatable, review-only

**Issue:** [#8](https://github.com/AvengersMobControl/avengers-stat-center/issues/8). The earlier approved **Space** graphic remains owned by `scripts/render-space-summary.py`. **Do not silently replace or restyle it.** This milestone adds sibling Piggy, Piggy Flash, and Kraken formats using its 2400×1500 navy/cyan/purple visual language. These *new* designs require leader visual signoff before they become approved broadcast templates.

## Make previews from the same accepted event ledger used by the live site

```bash
node scripts/export-event-summary.cjs approved-summary-release.json
python3 -m pip install Pillow==11.3.0

python3 scripts/render-event-summary.py reports/approved-summary-release.json reports/piggy-AVENGERS.png --kind piggy --clan AVENGERS
python3 scripts/render-event-summary.py reports/approved-summary-release.json reports/flash-AV2.png --kind flash --clan AV-2
python3 scripts/render-event-summary.py reports/approved-summary-release.json reports/kraken-AVENGERS.png --kind kraken --clan AVENGERS
# To replay an approved historical event rather than the latest recorded for a clan:
python3 scripts/render-event-summary.py reports/approved-summary-release.json reports/piggy-history.png --kind piggy --clan AVENGERS --event-id 'piggy|2026-10-11'
```

The exporter constructs the **canonical, approved** projection with `create()` and writes only under gitignored `reports/`. No Discord source, preliminary screenshots, or unapproved staging update can enter this pipeline. Rendering does not modify `data/approved-event-updates.json` or any canonical rewards. Each PNG has a sidecar `name.json` with source `projectionVersion`, `eventId`, event-time clan, image SHA-256 and explicit `readyToPost:false`/`discordPostingEnabled:false`.

## Immutable data/display rules

- The requested event is selected from **accepted final or partial** event rows; a revoked/missing event is rejected. With no event ID supplied, choose the latest active event with at least one **event-time clan** row, never filter by current roster membership. AVENGERS and AV-2 are independent; transfers do not change historic entries.
- Piggy and Piggy Flash use exact **lines**. Kraken uses **million damage** (not Space lightyears); never show or infer Kraken Stars. Piggy/Flash **Sparks per line** is from the matching result row where Sparks and lines are known. For Kraken, leave Sparks/Effort blank because units/award interpretation differ. A Flash PB is within Flash history, not a Piggy PB.
- PBs use `projection.people[].kinds[kind].pbs` for that exact event (actual previous/new, verified improvement); show returning-player PBs only. Distinguish **first tracked** from first-ever in-game. Higher wins and ties use the projection rules without inventing missing historical data.
- All totals labeled **KNOWN** sum only non-null values. Missing score/Sparks/Stars rows remain unknown, not zero awards. Partial events are labeled partial, even with multiple captured lobbies. Estimated Kraken Sparks are marked as such. Share % appears **only** when in reviewed event metadata; do not infer it from rewards.
- Comparisons show recorded totals/participant counts from the prior *same-kind, same-clan* accepted event; participants/coverage may differ. A percent shift in cumulative recorded work is not individual performance. Do not infer absent competitors, zero awards or first-ever achievements.
- Outputs are deterministic for the same canonical projection + event + clan and generated by Pillow. Long PB/first-tracked lists have an explicit “+N more” count rather than clipping silently; full data are in canonical site exports. Top-ten row list uses only recognized event-time competitors or explicitly “Unassigned account” when identity remains unresolved.

## CI, approvals, sending policy

PR and Pages workflows regenerate **six previews** (Piggy / Flash / Kraken × AVENGERS / AV-2) from the actual accepted projection, validate the full raster `2400×1500`, and run independent synthetic edge-case tests for unknown payouts, clan boundaries, PB transitions, first tracked, stale candidates, and deterministic SHA. PR artifacts: `event-summary-png-previews` with six PNGs and their manifest JSON sidecars. Review those outputs visually with the clan leader; automated tests verify source integrity and completeness flags, **not design approval**.

**Nothing is posted automatically.** No Discord send, retry or deletion is enabled and no message ID/posted-state ledger is changed. Once each new design is visually approved, retain a versioned immutable template identifier and implement an explicit dispatch plan keyed by **eventId + clan + canonical projectionVersion + template version**. A correction changing the source version must replace/review the earlier preview before considering a new post; duplicate keys must not resend. Posting remains blocked until separately authorized. The old Space renderer stays unchanged throughout this slice.
